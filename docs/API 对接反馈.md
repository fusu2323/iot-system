## 概述

本文档记录前端对接后端 API 接口时发现的问题和建议，供后端开发参考修复。

---

## 问题清单

### 🔴 严重问题

#### 1. 用户注册接口返回值不一致
- **接口**: `POST /api/auth/register`
- **文档说明**: 返回新创建用户的 ID (number)
- **问题**: 文档示例返回 `{ code: 200, data: 10 }`，但实际应该返回完整的用户信息或至少包含用户 ID
- **建议**: 统一返回格式，建议返回 `{ id: number }` 或完整用户信息
- **状态**: ⏳ 待确认

#### 2. 用户列表接口分页参数命名不统一
- **接口**: `GET /api/users` 和其他列表接口
- **文档说明**: 使用 `page` 和 `size` 作为分页参数
- **问题**: 需要确认后端实际使用的参数名是否与文档一致（有些后端框架使用 `pageNum`/`pageSize` 或 `current`/`limit`）
- **建议**: 统一所有列表接口的分页参数命名
- **状态**: ⏳ 待确认

---

### 🟡 一般问题

#### 3. 设备创建接口参数传递方式
- **接口**: `POST /api/devices?userId={userId}`
- **问题**: `userId` 作为查询参数传递而不是在请求体中，不符合 RESTful 最佳实践
- **建议**: 将 `userId` 放入请求体，或者从 Token 中解析用户 ID
- **状态**: ⏳ 待讨论

#### 4. 场景设备关联接口设计复杂
- **接口**: `POST /api/scenes/{id}/devices?deviceId={deviceId}&config={config}`
- **问题**:
  1. `config` 作为查询参数传递，URL 编码可能有问题
  2. 不支持批量添加设备
- **建议**:
  1. 使用请求体传递 `deviceId` 和 `config`
  2. 考虑支持批量操作
- **状态**: ⏳ 待讨论

#### 5. 偏好设置接口设计
- **接口**: `POST /api/preferences?userId={userId}`
- **问题**:
  1. `userId` 作为查询参数，但从安全角度应该从 Token 中获取
  2. `contentType` 枚举值文档中是 `MOVIE`，但前端业务中可能使用中文
- **建议**:
  1. 从 Token 解析用户 ID
  2. 明确前后端枚举值映射关系
- **状态**: ⏳ 待讨论

---

### 🟢 建议优化

#### 6. 响应消息字段命名
- **问题**: 文档中返回消息字段是 `message`，但有些接口描述使用不同说法
- **建议**: 统一使用 `message` 字段
- **状态**: ✅ 已确认统一

#### 7. 时间格式统一
- **问题**: 文档中时间格式为 `"2026-03-12 10:00:00"` (字符串)
- **建议**:
  1. 统一使用 ISO 8601 格式 `"2026-03-12T10:00:00Z"`
  2. 或者统一时间戳格式
- **状态**: ⏳ 待确认

#### 8. 设备类型枚举值
- **文档**: `TV/SPEAKER/LIGHT/AIR_CONDITIONER...`
- **问题**: 前端展示需要中文映射
- **建议**: 提供完整的枚举映射表或后端返回时包含中文显示名
- **状态**: ⏳ 待确认

## 前端适配说明

### 1. Axios 拦截器配置
前端已配置统一响应拦截器，自动处理：
- Token 注入（`Authorization: Bearer xxx`）
- 401 自动跳转登录
- 业务错误提示

### 2. 接口调用示例
```typescript
// 登录
import { login } from '@/api/auth';

const response = await login({
  username: 'admin',
  password: 'admin123'
});
// response 已自动解包为 data 部分

// 获取用户列表
import { getUserList } from '@/api/user';

const result = await getUserList({
  page: 1,
  size: 10,
  keyword: '张'
});
```
